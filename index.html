AT-A-GLANCE REFERENCE

The stack behind the memory.

Everything below runs inside the single npm package. No external services, no vector cloud, no sidecar database to babysit.

ScopeKeep technical reference
ComponentDetails
StorageOne encrypted SQLite database per workspace under ~/.scopekeep/workspaces/. AES encryption via SQLCipher multiple-ciphers; plaintext databases are rekeyed automatically on first open.
Temporal modelBi-temporal records with validity and assertion windows. Point-in-time review via get_memories_as_of; updates are versioned, never overwritten silently.
RetrievalHybrid FTS5 (BM25) + sqlite-vec KNN over 384-dim MiniLM embeddings, merged with keyword boost, reputation weighting and MMR diversification. Falls back to deterministic hash embeddings offline.
EvidenceOptional signed attestation per retrieval: Ed25519 signature appended to a SHA-256 hash chain, query text hashed by default. Verifiable with verify_attestation.
SafetyCredential redaction applied when memories are stored; contradiction handling proposes reviews instead of mutating history; workspace purge verifies zero remaining rows, checkpoints the WAL and vacuums.
MaturityPublic alpha. Direct MCP retrieval is the reliable path. Passive editor transcript capture is opt-in and not launch-grade on Windows. Known limitations are documented in the README — nothing here hides them.
TransportMCP over stdio for VS Code, Cursor, Claude Code, Windsurf and friends. Optional loopback HTTP gateway, authenticated, disabled by default in production.
ClientsAny MCP-compatible client. Generated configs for VS Code, Cursor and Claude Code via scopekeep init --mcp=<client>.

GOVERNED MEMORY, NOT SILENT MUTATION

Conflicts become proposals. History stays honest.

When a new fact contradicts a stored one, most memory tools quietly overwrite. ScopeKeep versions both sides, links them in a contradiction chain, and returns a review proposal — you decide which version is true. Consolidation candidates are proposed the same way, never auto-merged into Frankenstein summaries.

Every retrieval can be recorded as an attestation: who asked, what query, which memories came back, signed with Ed25519 and chained so nothing can be removed retroactively. Combined with point-in-time reconstruction (get_memories_as_of), you can answer the question auditors actually ask: what did the agent know at the moment it acted?

Purge is verifiable, not promised. Deleting a workspace requires typing its exact ID, deletes all owned rows, verifies none remain, checkpoints the WAL and vacuums the file. The privacy export produces a complete, human-readable record of everything the workspace owns first.

QUESTIONS, ANSWERED

Questions about storage, evidence, and control.

Straight answers, including the limits. The README documents known alpha issues in the same spirit.

What is ScopeKeep?

A local-first memory layer for AI coding tools. Durable project facts live in an encrypted SQLite database per workspace and are exposed to any MCP client — Claude Code, Cursor, VS Code, Windsurf and others.

Is it free? What does freemium mean here?

The core is free and MIT-licensed — the full local engine, no account, no telemetry. ScopeKeep is freemium: optional paid tiers (team features, sync, managed policy controls) are planned for later; specifics and pricing will be announced when they exist. The local core stays free.

How mature is it?

Public alpha. The retrieval engine, storage, encryption, evidence chain and CLI are tested by a 30-file suite that runs in CI. Passive editor transcript capture is opt-in and not launch-grade on Windows — use direct MCP calls. The README's "Known alpha limitations" section is the honest list.

How is this different from CLAUDE.md or Cursor Memories?

Rule files are static text you maintain by hand; editor memories stay inside one editor. ScopeKeep is a store your agents read and write across tools — with hybrid semantic search, versioning, conflict proposals and signed evidence. Most teams use rule files for stable conventions and ScopeKeep for accumulated knowledge.

Where does my data live, exactly?

In one encrypted database per workspace under ~/.scopekeep/workspaces/<id>/scopekeep.db, keyed by a canonical repository-root hash. Keys stay on your machine; nothing syncs anywhere unless you export it yourself.

What do the signed attestations actually prove?

That a specific retrieval happened: the query (hashed by default), the memories returned, the agent identity and timestamp — signed with Ed25519 and chained so entries cannot be dropped later. It is audit evidence, not a certification of anything.

Does ScopeKeep make me GDPR or HIPAA compliant?

No blanket claim is made, on purpose. It provides technical controls — verified purge, exports, audit chains — that can support your own compliance program. Legal classification depends on your deployment. See the privacy manifest in the repo.
